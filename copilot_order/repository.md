## 前提条件・制約

### 技術的制約

- バックエンドは Rust を使用言語としてください。現在は Rust + `axum` + `tokio` を使用しています。
- 既存の Misskey 系（`127.0.0.1:3000`）と競合するポート設計は避けてください。現在の待受は `127.0.0.1:3001` です。
- 外部公開は Nginx 経由を前提とし、アプリが直接 443/TLS 終端を持つ前提で設計しないでください。

### 運用上の制約

- AWS EC2 上の Ubuntu マシン上でサービスを稼働し、Android クライアント向けに配信する運用としてください。
- 公開ホストは `life.pal-mate.jp` を前提に扱ってください。ドメインが新たに必要になったときは、さらにサブドメインを切ることを検討してください。
- `mi.pal-mate.jp` 側の既存構成に影響する変更は分離して検討してください。
- 公開経路は Cloudflare / DNS 条件の影響を受けます。経路前提（DNS only 可否など）が曖昧な場合は、推測で進めず確認してください。
- EC2 上での常駐は `life-management.service`（systemd）前提です。起動方式を変更する提案を行う場合は、運用手順とロールバック手順の更新を前提にしてください。

### セキュリティ・プライバシー要件

- mTLS 必須方針です。クライアント証明書なしアクセスを前提にした設計・実装・検証手順は採用しないでください。
- クライアント証明書は端末ごとに分離する前提です（例: Windows用 / Android用）。証明書の使い回しを前提にしないでください。
- 配布用 `.p12` の取り扱い・残置には注意してください。秘密情報の平文残置や不要なサーバ保存を前提にした運用は提案しないでください。

## 現在のシステム構成

### 主なディレクトリと役割

- `./backend_prototype` : 試作版の cargo プロジェクトです。試作が終わるまでの間、ソースコードはすべてここに配置してください。
- `./copilot_context` : [gen] 参照。
- `./copilot_order` : [gen] 参照。
- `./copilot_output` : [gen] 参照。
- `./formal_outputs` : [gen] 参照。
- 試作が完了次第、メインプロジェクトフォルダを cargo にて作成してください。

### 主要コンポーネント

- Rustバックエンド（`./backend_prototype`）
    - `axum` + `tokio` による試作Webサーバです。
    - 現在は `127.0.0.1:3001` で待受し、`/`（HTML）、`/health`、`/api/daily-time` を提供します。
    - `daily-time` は「同一JST日内で同じ値」を返す挙動を前提にしてください。
- Nginx（EC2上の公開・終端レイヤ）
    - `life.pal-mate.jp` への HTTPS 公開を担当し、Rustバックエンドへリバースプロキシします。
    - mTLS を有効化した構成で運用している前提で扱ってください。
    - 既存の `mi.pal-mate.jp`（Misskey系）と共存するため、ポート・server block の衝突を避けてください。
- mTLS クライアント証明書運用
    - PoC段階からクライアント証明書必須です。
    - 端末ごとに証明書を分離する前提です（例: Windows用とAndroid用）。
    - 配布用 `.p12` の取り扱い・残置には注意し、作業時は漏えい防止を優先してください。
- Cloudflare / DNS 経路
    - `life` サブドメイン公開では Cloudflare 経路条件（DNS only 可否）が構成判断に影響します。
    - 経路前提が曖昧な場合は、推測で進めず確認してください。
- 運用コンポーネント（EC2）
    - `life-management.service`（systemd）による常駐運用を前提に扱ってください。
    - デプロイ・ロールバック・証明書更新は手順書ベースで再現可能に維持してください。

## 採用技術と採用理由

- Rust
    - バックエンド実装言語です。単体バイナリ化しやすく、EC2上での常駐運用（systemd）と相性が良いため採用しています。
- `axum`
    - HTTP ルーティングと API 実装を簡潔に構成できるため採用しています。現行の `/`、`/health`、`/api/daily-time` もこの前提で実装されています。
- `tokio`
    - `axum` 実行基盤の非同期ランタイムとして採用しています。
- Nginx
    - 公開終端（443/TLS）とリバースプロキシを担当するため採用しています。アプリ直公開ではなく、Nginx 経由の運用を前提にしてください。
- mTLS（相互TLS）
    - PoC 段階からアクセス制御を強制するため採用しています。クライアント証明書必須・端末別証明書の運用を前提にしてください。
- Let's Encrypt
    - `life.pal-mate.jp` のサーバ証明書を実運用可能な形で発行・更新するため採用しています。
- Cloudflare（DNS/経路管理）
    - 公開経路管理に関与するため採用しています。DNS only 可否など、経路条件が不明な場合は確認を優先してください。
- AWS EC2（Ubuntu）
    - 現在のホスティング基盤として採用しています。常駐プロセスは `life-management.service`（systemd）前提です。
    - もともとあった misskey 用サーバを流用しています。負荷上限は大きくないので適時確認してください。
- PowerShell（検証補助）
    - Windows 側の検証手順・再現実行のために採用しています（`./copilot_output/backend_prototype_validation.ps1`）。
